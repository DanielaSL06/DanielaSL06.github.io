01. Análisis de Datos

Análisis estadístico del impacto del uso de herramientas de Inteligencia Artificial en el rendimiento académico. Incluye limpieza de datos, matriz de correlación de Pearson, regresión lineal y prueba de hipótesis con campana de Gauss.

Tecnologías: Python, pandas, NumPy, SciPy, Matplotlib, Seaborn.

Ver detalles Ver código
Ver caso de estudio completo

Descripción

Estudio estadístico sobre el impacto del uso de herramientas de Inteligencia Artificial en el rendimiento académico de estudiantes universitarios, a partir de datos recopilados mediante formularios.

Requerimientos del cliente

  • Procesar un conjunto de datos real (CSV/Excel).
  • Limpiar la información: eliminar duplicados e imputar valores faltantes.
  • Calcular estadística descriptiva (media, mediana, moda, mínimo, máximo y desviación estándar).
  • Obtener la matriz de correlación de Pearson entre las variables.
  • Modelar regresiones lineales de tres variables relacionadas con la IA frente al promedio académico.
  • Realizar una prueba de hipótesis bilateral (α = 0.05) con su representación gráfica.

¿Cómo se diseñó la solución?

Se dividió el trabajo en dos módulos: analisis.py (limpieza, estadística descriptiva, correlación y regresión) e hipotesis.py (prueba de dos colas y campana de Gauss). Se definieron las variables independientes (uso de IA, tiempo ahorrado y percepción de mejora) y la dependiente (promedio), eligiendo Python por su ecosistema de análisis de datos.

¿Cómo se implementó la solución?

Con pandas y NumPy para la carga y limpieza; scipy.stats (linregress) para obtener r, r² y el p-value; seaborn/matplotlib para el mapa de calor de correlación y las gráficas de dispersión con recta de tendencia; y la campana de Gauss con zonas de aceptación/rechazo, Z crítico ±1.96 y la ubicación del Z calculado (17.744).

¿Cuál fue el resultado?

Se obtuvieron los modelos de regresión con sus coeficientes, correlaciones y significancias, además de las gráficas (mapa de calor, dispersión y campana de Gauss). El Z calculado cae en la zona de rechazo de H0, lo que aporta evidencia estadística de una relación significativa entre las variables.

Aplicación web full-stack con API RESTful para administrar proyectos y tareas dependientes. CRUD completo, base de datos relacional SQLite y una interfaz SPA que consume los servicios de forma asíncrona.

Tecnologías: Python, Flask, SQLite, SQL, HTML5, CSS3, JavaScript (fetch / async-await).

Descripción

Aplicación web full-stack basada en una API RESTful para administrar proyectos y tareas dependientes, con base de datos relacional SQLite y una interfaz que consume los servicios de forma asíncrona.

Requerimientos del cliente

  • CRUD completo para dos entidades relacionadas (proyectos y tareas).
  • API REST que responda en formato JSON.
  • Base de datos con clave primaria y clave foránea para mantener la relación.
  • Interfaz web que consulte y modifique los datos sin recargar la página.
  • Consultas parametrizadas para evitar inyección SQL.

¿Cómo se diseñó la solución?

Arquitectura cliente-servidor en tres capas: modelo de datos (SQLite), backend (Flask) y frontend (SPA). Se definieron los endpoints REST: GET/POST /proyectos, GET/PUT/DELETE /proyectos/<id> y sus equivalentes para /tareas.

¿Cómo se implementó la solución?

Con app.py (Flask + sqlite3): creación de las tablas con PK AUTOINCREMENT y FOREIGN KEY, transacciones con commit() y bloques try/except/finally, placeholders ? y respuestas con jsonify(). El frontend usa fetch() con async/await para renderizar, crear, buscar, editar y eliminar registros.

¿Cuál fue el resultado?

Una API funcional con CRUD completo y una interfaz que gestiona proyectos y tareas en tiempo real, con persistencia en SQLite y validaciones básicas.

03. Sensores IoT

Arquitectura de ingesta de telemetría IoT en tiempo real. Un servidor Flask recibe los datos de los sensores y los persiste de forma dual (JSON y CSV), mientras un emulador envía lecturas de temperatura y humedad periódicamente.

Tecnologías: Python, Flask, requests, JSON, CSV, IoT.

Ver detalles Ver código
Ver caso de estudio completo

Descripción

Simulación de una arquitectura de ingesta de datos IoT: un servidor Flask recibe telemetría de sensores y la persiste en dos formatos, mientras un emulador envía lecturas periódicamente.

Requerimientos del cliente

  • Recibir por HTTP (POST) paquetes JSON con temperatura, humedad y timestamp.
  • Persistir los datos en dos formatos: JSON (para el sistema) y CSV (para hojas de cálculo).
  • Calcular estadísticas básicas en consola conforme llegan los datos.
  • Simular un dispositivo que envíe lecturas de forma continua.

¿Cómo se diseñó la solución?

Dos módulos: appSensores.py (servidor Flask con los endpoints /sensores y /estadisticas y persistencia dual) y simuladorSensor.py (cliente que genera y envía telemetría). Flujo: dispositivo → POST JSON → servidor → persistencia + métricas.

¿Cómo se implementó la solución?

Endpoint POST /sensores con Flask; escritura en datosSensor.json (json.dump) y datosSensor.csv (csv.writer con encabezados); cálculo del promedio de humedad y temperatura máxima/mínima; el simulador usa requests.post con valores aleatorios (20-30 °C y 40-60 %) cada 5 segundos.

¿Cuál fue el resultado?

El servidor registró cada envío con respuesta HTTP 201, generó los archivos JSON y CSV y mostró las métricas en consola (promedios, máximos y mínimos) en tiempo real.

Una aplicación con operaciones concurrentes y persistencia transaccional en SQL Server, que evita bloqueos del hilo principal y mantiene la integridad de la información. (El repositorio incluye la solución y capturas del código.)

Descripción

Diseño e implementación de redes inalámbricas, desde entornos SOHO hasta infraestructura empresarial centralizada con controlador WLC, autenticación RADIUS 802.1X, VLANs y FlexConnect.

Requerimientos del cliente

  • Configurar una red inalámbrica residencial con DHCP y seguridad WPA2-Personal.

  • Segmentar el tráfico por VLANs y autenticar usuarios con 802.1X (RADIUS).

¿Cómo se diseñó la solución?

¿Cómo se implementó la solución?

Router con DHCP (20 usuarios) y DNS; SSID en 2.4 GHz con WPA2-AES; WLC administrado por HTTPS (192.168.100.254) con subinterfaces; RADIUS externo (10.6.0.254); FlexConnect con conmutación y autenticación local; verificación con ipconfig, ping y navegación al servidor web.

¿Cuál fue el resultado?

Los clientes residenciales obtuvieron direccionamiento en 192.168.6.0/27, la autenticación 802.1X en SSID-5 funcionó correctamente y se confirmó la conectividad de extremo a extremo con ping y acceso al servidor web (203.0.113.78).

Descripción

Instalación, endurecimiento (hardening) y administración de MySQL 8.0 sobre Ubuntu Server, con operaciones DDL y DML sobre una base de datos relacional.

Requerimientos del cliente

  • Instalar MySQL Server en Ubuntu Server.
  • Endurecer la seguridad con mysql_secure_installation.
  • Configurar la autenticación por socket Unix para el usuario root.
  • Crear una base de datos y una tabla y ejecutar operaciones DDL/DML (INSERT, SELECT, UPDATE).

¿Cómo se diseñó la solución?

Se siguió el ciclo de administración de un SGBDR: instalación y verificación del servicio, endurecimiento, modelado de una base de datos de práctica (practica4 con la tabla alumnos) y operaciones SQL, todo en una máquina virtual (VirtualBox).

¿Cómo se implementó la solución?

apt install mysql-server y systemctl status mysql; mysql_secure_installation (eliminar usuarios anónimos, deshabilitar root remoto, borrar la base test); autenticación auth_socket; CREATE DATABASE practica4; CREATE TABLE alumnos (PK AUTO_INCREMENT, matricula UNIQUE, promedio DECIMAL); INSERT, SELECT con WHERE, UPDATE y DESCRIBE.

¿Cuál fue el resultado?

Un servidor MySQL 8.0 endurecido y operativo, con la base de datos practica4 y la tabla alumnos, consultas verificadas (filtros y actualización de promedios) y evidencia capturada en la terminal.
